# day-by-day TOEIC — 프론트엔드 설계 스펙

- 작성일: 2026-08-04
- 상태: 사용자 승인 완료 (구현 전)
- 범위: 프론트엔드 전용 (백엔드는 추후 별도)

## 1. 개요

말해보카/스픽 스타일의 토익 데일리 학습 웹 서비스. 달력 날짜 기반으로 매일 영단어와 문장을 학습하고, 배운 범위에서 복습 시험을 본다.

- 대상: 여러 사람이 쓰는 서비스 지향. 단, 첫 버전은 백엔드 없이 프론트만 만들고 진도는 브라우저 localStorage에 저장한다.
- 데이터: 정해진 스키마의 JSON 파일을 레포에 추가하는 방식. 운영자(이현복)가 직접 편집한다.
- 로그인/계정: 첫 버전 제외. 백엔드 도입 시 함께 추가한다.

## 2. 기술 구성

- Next.js (App Router) + TypeScript + Tailwind CSS
- 상태 관리 라이브러리 없음 (React 기본 훅)
- 외부 UI/달력 라이브러리 없음 (달력은 월 그리드 직접 구현)
- 첫 버전 제외 기능: 로그인, 듣기(TTS), 토익 모의고사

## 3. 화면 구성

| 경로 | 화면 | 내용 |
|---|---|---|
| `/` | 홈 | 오늘 날짜의 학습 카드(시작/이어하기/완료 상태), 스트릭·출석 요약, 미니 달력 |
| `/calendar` | 달력 | 월 단위 달력. 콘텐츠 있는 날 표시, 완료/미완료/놓친 날 구분. 지난 날짜도 눌러서 학습 가능 |
| `/learn/[date]` | 학습 세션 | 해당 날짜 학습을 한 흐름으로 진행 (아래 4장) |
| `/learn/[date]/result` | 결과 | 정답률, 틀린 문항 목록. 틀린 문항은 오답노트에 자동 저장 |
| `/review` | 복습 시험 | 범위 선택(최근 7일 / 전체 / 오답만) → 시험 → 결과 |
| `/notes` | 오답노트 | 틀린 단어·문장 목록, 다시 풀기 |
| `/stats` | 통계 | 스트릭, 누적 학습 단어 수, 날짜별 정답률 |

학습 세션(`/learn/[date]`)은 전체화면 몰입형 UI로 한다: 상단 진행바, 문제 하나씩 표시, 나가기 버튼. 나머지 화면은 일반 페이지 레이아웃(상단 네비게이션)이다.

## 4. 학습 플로우 (한 날짜 기준)

한 세션은 다음 단계를 순서대로 진행한다.

1. **단어 훑기** — 오늘의 단어를 카드로 넘겨보기 (단어·품사·뜻·예문·예문 해석)
2. **단어 뜻 퀴즈** — 4지선다. 단어를 보여주고 뜻을 고른다. 오답 보기 3개는 같은 날짜의 다른 단어 뜻에서 우선 뽑고, 부족하면 전체 단어 풀에서 채운다
3. **문장 빈칸** — 문장의 빈칸(`blankWord` 자리)에 들어갈 단어를 4지선다로 고른다 (보기 = 정답 + `distractors` 3개). Part 5 형식
4. **문장 조합** — 한글 해석(`ko`)을 보고, 섞인 단어 칩을 순서대로 눌러 문장을 완성한다
5. **틀린 문제 재도전** — 2~4단계에서 틀린 문항을 세션 끝에 한 번 다시 푼다. 두 번 틀려도 세션은 완료된다
6. **결과** — 정답률 표시(재도전 전 첫 시도 기준), 틀린 문항을 오답노트에 적재, 해당 날짜 완료 처리

채점 기준: 문항별 첫 시도의 정오만 정답률과 오답노트에 반영한다. 재도전 결과는 기록하지 않는다.

## 5. 데이터 스키마

### 5.1 날짜별 콘텐츠 — `public/data/days/YYYY-MM-DD.json`

```json
{
  "date": "2026-08-04",
  "title": "Day 1 — 계약과 협상",
  "words": [
    {
      "id": "w-negotiate",
      "word": "negotiate",
      "pos": "v.",
      "meaning": "협상하다",
      "example": "We need to negotiate the terms.",
      "exampleKo": "우리는 조건을 협상해야 한다."
    }
  ],
  "sentences": [
    {
      "id": "s-20260804-01",
      "text": "The manager will negotiate the contract next week.",
      "ko": "매니저가 다음 주에 계약을 협상할 것이다.",
      "blankWord": "negotiate",
      "distractors": ["postpone", "estimate", "submit"]
    }
  ]
}
```

규칙:
- `id`는 전체 데이터에서 유일해야 한다 (오답노트가 id로 참조).
- `blankWord`는 `text` 안에 정확히 한 번 등장해야 한다.
- `distractors`는 정확히 3개.
- 문장 하나가 빈칸 모드와 조합 모드에 모두 쓰인다 (조합 모드는 `text`를 공백 기준 토큰으로 쪼개 셔플).

### 5.2 날짜 인덱스 — `public/data/index.json`

```json
{
  "days": [
    { "date": "2026-08-04", "title": "Day 1 — 계약과 협상" }
  ]
}
```

달력과 홈 화면은 이 인덱스만 읽는다. 날짜별 파일은 학습 시작 시 로드한다.

### 5.3 데이터 검증 스크립트

`npm run validate-data`: 모든 날짜 파일에 대해 스키마·id 중복·`blankWord` 포함 여부·distractors 개수·인덱스와 파일의 일치를 검사한다. 데이터 추가 후 오타를 잡는 용도.

### 5.4 시드 데이터 (이번 구현 범위에 포함)

- 2026-08-04부터 연속 14일치를 미리 제작해 넣는다.
- 하루 분량: 단어 10개 + 문장 5개.
- 어휘는 토익 빈출 비즈니스 어휘(계약, 회의, 인사, 마케팅, 출장, 재무 등 주제별)로 구성하고, 문장은 Part 5 스타일의 비즈니스 문장으로 작성한다.
- 이후 데이터 추가는 운영자가 같은 스키마로 JSON을 편집한다.

## 6. 진도 저장 (localStorage)

`progressRepo`가 관리하는 데이터:

- **날짜별 학습 기록**: 완료 여부, 완료 시각, 단계별 정답률
- **오답노트**: 틀린 문항 참조 목록 (`{ type: "word" | "blank" | "arrange", itemId, date, wrongCount }`). 다시 풀어 맞히면 목록에서 제거
- **복습 시험 기록**: 시험 일시, 범위, 정답률
- **스트릭**: 별도 저장 없이 날짜별 학습 기록에서 계산 (연속 완료일 수)

## 7. 데이터 접근 레이어 (백엔드 교체 전제)

화면 컴포넌트는 아래 두 인터페이스만 바라본다. 백엔드 도입 시 구현체만 교체한다. 이 두 개 외에 추가 추상화 레이어는 두지 않는다.

- `contentRepo` — 콘텐츠 조회. 첫 구현: `public/data/`의 JSON fetch. 추후: `GET /api/days`, `GET /api/days/{date}`
- `progressRepo` — 진도 저장/조회. 첫 구현: localStorage. 추후: 서버 API

## 8. 복습 시험

- 범위 선택: 최근 7일 / 전체 학습분 / 오답만
- 출제: 선택 범위에서 학습 완료된 날짜의 단어·문장으로 랜덤 출제 (모드는 단어 뜻 퀴즈·문장 빈칸 혼합, 총 20문항. 범위 내 문항이 20개 미만이면 있는 만큼)
- 결과: 정답률 표시, 틀린 문항은 오답노트에 적재

## 9. 엣지 케이스

- 콘텐츠 없는 날짜 접근 → "이 날은 콘텐츠가 없어요" 안내 후 달력으로 유도
- 학습 중 이탈 → 중간 상태를 저장하지 않는다. 다시 들어오면 세션 처음부터
- 오늘 날짜 콘텐츠가 없으면 → 홈에서 가장 최근의 미완료 날짜를 안내
- 학습 완료한 날짜 재입장 → 다시 학습 가능 (기록은 최신 완료로 갱신, 정답률은 덮어씀)
- localStorage가 비어 있으면(새 브라우저) → 진도 없음 상태로 정상 동작

## 10. 테스트

- 데이터 검증 스크립트를 시드 데이터 전체에 통과시킨다.

- 화면은 수동 확인 (첫 버전에서 E2E는 두지 않는다).
