# 데일리 CS 셀프 스터디 설계

작성일: 2026-11-25

이 문서는 day-by-day-TOEIC repo를 **전면 교체**한다. 기존 스펙(2026-08-04 토익 프런트, 08-06 Supabase 배포, 08-06 단어 게임 SRS, 08-09 CS 카드 트랙)은 이 문서로 대체되고, 토익 코드와 Supabase 연동은 제거한다.

---

## 1. 왜 만드는가

- 실제 면접, 모의면접, 직접 만든 기술면접 문항에서 받은 **백엔드/CS 질문**에 대해, 내가 실제로 얼마나 설명할 수 있는지 모른다.
- 질문 하나를 잡고 1시간~하루 공부 → 조사 → **내 말로 설명** → **점수**로 이해도를 확인한다.
- 이 과정을 매일 기록하는 **나만의 공부 블로그**(읽은 기술 블로그, 오늘 공부한 것, 개발한 것, 회고)로 남긴다.
- 로컬에서 먼저 쓰고, 소셜/블로그 게시는 나중에 정한다.

**성공**: 질문별 이해도를 직관적으로 본다 — 캘린더, 그래프, 꼬리질문으로 파고들기.

## 2. 목표 · 비목표 · 실패 조건

**목표**
- 질문 은행 → 몰입형 풀이 화면(잡다 인적성 스타일) → 글/음성 설명 제출 → 자기채점
- Claude Code `/채점`으로 AI 채점, 꼬리질문 자동 생성
- 캘린더, 점수 그래프, 꼬리질문 트리, 날짜별 블로그 뷰
- 하루 회고(읽은 글, 개발한 것, 한 줄 회고) 기록

**비목표 (이번 범위 밖)**
- 폰 지원 (나중에 한다. 데이터를 평범한 md로 두어 길만 열어 둔다)
- 로그인, 서버 배포, 소셜 자동 게시
- 면접 대비 모드 ("내 사례" 채점 항목)
- 토익 기능 유지

**실패 조건 (동작해도 실패인 것)**
- 자기채점이 30초 안에 안 끝난다 → 매일 못 쓴다
- 기록이 앱 밖에서 못 읽는 형식이다 → 블로그로 못 옮긴다
- 앱 안에서 AI API를 호출한다 → 결정과 다르다 (비용)

## 3. 제약

- 맥 + 크롬, `npm run dev` 로컬 서버로만 쓴다.
- 기존 셋업 유지: Next.js 16.3, React 19, Tailwind 4, vitest. Next.js 16은 학습 데이터와 API가 다를 수 있으니 `node_modules/next` 안의 문서를 확인하고 쓴다 (AGENTS.md).
- 새 npm 패키지는 사용자에게 제안 후 추가한다 (사용자 전역 규칙).
- 데이터는 이 repo의 `data/` 폴더, git으로 기록·백업한다.

## 4. 접근 방식

| 방식 | 내용 | 판단 |
|---|---|---|
| **A. Next.js 로컬 서버 + md 파일** | 기존 앱을 갈아엎고 서버 라우트가 `data/`의 md를 읽고 쓴다 | **선택.** 풀이 화면·타이머·녹음·뷰를 한 앱에 담을 수 있는 유일한 방식. 기존 셋업 재사용. 폰 이전 시 저장 계층만 교체 |

| C. 단일 HTML (`음성모의면접.html` 방식) | 서버 없음 | 크롬 File System Access 의존, 매번 폴더 권한, 뷰가 커지면 관리 불가 |

사용자가 A를 골랐다 (2026-11-25).

## 5. 하루 흐름

```
① 질문 고르기   질문 은행에서 오늘 할 질문 선택
② 공부          타이머가 돈다. 읽은 링크와 메모를 쌓는다 (1시간~하루, 중간에 닫았다 다시 열어도 이어짐)
③ 설명 제출     글 쓰기  또는  말로 설명(녹음 + 크롬 받아쓰기 → 텍스트 수정 가능)
④ 자기채점      기준표 항목별 0 / 절반 / 만점 선택 → status: pending
⑤ /채점         Claude Code에서 실행 → AI 점수, 빠진 개념, 꼬리질문 기록 → status: graded
⑥ 꼬리질문      생성된 꼬리질문을 새 질문으로 이어서 공부
⑦ 회고          그날의 읽은 글 / 개발한 것 / 한 줄 회고
```

## 6. 채점 (사용자 결정)

자기채점 + Claude Code 채점 혼합. 앱은 AI를 호출하지 않는다.

**기준표 — 공부 모드 (100점)**

| 항목 | 배점 | 보는 것 |
|---|---|---|
| 개념 정확도 | 60 | 틀린 말 없이 핵심을 짚었나 |
| 트레이드오프·이유 | 40 | 왜 쓰는지, 무엇을 포기하는지 말했나 |

- 자기채점은 항목마다 0 / 절반 / 만점 3단계 (개념 0·30·60, 트레이드오프 0·20·40).
- AI 채점은 같은 기준표로 0~만점 정수.
- **"내 사례"는 점수 없음.** 선택 메모 칸으로만 두고 나중 면접 대비 재료로 쓴다.
- **착각 지수** = 자기점수 − AI점수. 양수가 크면 "안다고 착각하는 질문". 그래프와 목록에서 따로 표시한다.

**`/채점` 명령**: 프로젝트 Claude Code 명령으로 repo에 둔다. 동작:
1. `data/study/` 에서 `status: pending` 파일을 모두 찾는다
2. 질문 파일(질문 + 참고 답안)과 내 설명을 읽고 기준표로 채점
3. 공부 기록 파일에 `ai_score`, 항목별 점수, 빠진 개념, 꼬리질문 2~3개를 쓰고 `status: graded`
4. 꼬리질문마다 `parent`가 설정된 새 질문 파일을 `data/questions/`에 만든다 (같은 질문이 이미 있으면 새로 만들지 않고 연결)

## 7. 데이터 (파일 저장 방식)

```
data/
  questions/
    os-process-vs-thread.md          # 질문 1개 = 파일 1개, 파일명 = id
  study/
    2026-11-25/
      os-process-vs-thread.md        # 그날 그 질문 공부 기록 = 블로그 글 초안
      os-process-vs-thread.webm      # 말로 설명했을 때 녹음
    2026-11-25.md                    # 그날 회고
```

같은 질문을 다른 날 다시 공부하면 그 날짜 폴더에 새 기록이 생긴다. 점수 추이는 이 기록들로 그린다. 캘린더·그래프·트리는 매번 파일을 읽어 계산하고 별도 집계 파일은 두지 않는다.

**질문 파일**
```md
---
id: os-process-vs-thread
topic: 운영체제
source: mock              # real(실면접) | mock(모의면접) | self(자작) | followup(꼬리질문)
from: 미리디 모의면접 2026-09-30
parent: null              # 꼬리질문이면 부모 질문 id
created: 2026-11-25
---
프로세스와 스레드의 차이를 설명해 주시겠어요?

## 참고 답안
(있으면. 풀이 화면에서는 제출 전까지 숨긴다)
```

**공부 기록 파일**
```md
---
question: os-process-vs-thread
date: 2026-11-25
minutes: 75
mode: write               # write | voice
status: pending           # draft | pending | graded
self: { concept: 30, tradeoff: 40 }
self_score: 70
ai: { concept: 45, tradeoff: 20 }   # /채점 후
ai_score: 65
links:
  - https://...
---
## 공부 메모
...
## 내 설명
...
## 내 사례 (선택)
...
## 채점 결과 (/채점이 씀)
- 빠진 개념: ...

```

`status: draft`는 공부 중(제출 전) 상태. 중간에 닫아도 `minutes`와 메모가 저장돼 이어서 할 수 있다.

```md

- [제목](url) — 한 줄

```

## 8. 질문 가져오기

1차 출처는 RESUME 폴더의 음성모의면접 문항 은행 (`{no, t, q, a, mine, pri}` 구조의 `var CFG = {...}` JS 파일):

| 파일 | 문항 수 | source |
|---|---|---|
| `04_면접·코테/음성모의면접_문항_미리디_CS전체_20260930.js` | 37 | mock |
| `04_면접·코테/음성모의면접_문항_미리디_약점12_20260929.js` | 13 | mock |
| `04_면접·코테/음성모의면접_문항.js` | 7 | mock |

(RESUME 루트: `~/Library/Mobile Documents/com~apple~CloudDocs/me/RESUME/`)

- 가져오기 스크립트 1개: `t` → topic, `q` → 질문, `a` → 참고 답안(HTML 태그는 마크다운으로), `mine` → 버린다(공부 모드에서 안 씀).
- id는 질문 내용으로 만든 slug. 이미 있는 id는 덮어쓰지 않는다.
- 실제 면접 기록(`06_지원완료/*/` 의 녹취록·예상질문)은 앱의 "질문 추가" 화면으로 수동 입력한다 (source: real). 자동 추출은 하지 않는다.

## 9. 화면

**풀이 화면 (잡다 인적성 스타일, 핵심 화면)** — 전체화면 몰입형
```
┌──────────────────────────────────────────────┐
│ 운영체제 · 모의면접            ⏱ 01:15:32   [나가기] │
├──────────────────────────────────────────────┤
│                                              │
│   프로세스와 스레드의 차이를 설명해 주시겠어요?       │
│                                              │
├──────────────────────────────────────────────┤
│ [공부 메모] [링크]                              │
│ ...                                          │
├──────────────────────────────────────────────┤
│ 설명 제출:  (글 쓰기) (말로 설명 ●REC)            │
│                                [제출 → 자기채점] │
└──────────────────────────────────────────────┘
```
제출 후 자기채점 → 참고 답안 공개 순서 (답안을 먼저 보면 자기채점이 오염된다).

**홈 / 캘린더** — 월 달력. 날짜 칸 색 농도 = 그날 공부한 질문 수, 칸 안에 평균 점수. 날짜 클릭 → 그날 블로그 뷰.

**그래프** — 토픽별 평균 점수 막대, 질문별 점수 추이(자기 vs AI 두 선), 착각 지수 큰 순 목록.

**꼬리질문 트리** — 루트 질문 → 꼬리질문 → … 노드마다 최근 AI 점수(없으면 자기점수, 둘 다 없으면 "미학습").

**질문 은행** — 토픽·출처·점수로 필터. 미학습 / 채점 대기 / 낮은 점수 순 정렬. "질문 추가" 버튼.

**블로그 뷰 (날짜별)** — 그날의 공부 기록들 + 회고를 한 페이지로. 회고 작성/수정도 여기서.

## 12. 빌더 검토 후 Claude가 정한 것

설계 검토에서 나온 질문을 Claude가 정했다. 사용자가 바꿀 수 있다.

- **동시 쓰기**: 앱은 `draft` 파일만 쓰고, `/채점`은 `pending` 파일만 쓴다. 상태로 영역이 나뉘므로 잠금은 두지 않는다.
- **같은 날 같은 질문**: 하루 한 질문당 기록 하나. 같은 날 다시 열면 그 `draft`를 이어서 한다. 이미 `pending`/`graded`이면 `<id>-2.md`로 새 기록을 만든다.
- **채점 후 수정**: `graded`는 확정이다. 다시 하고 싶으면 새 기록을 만든다. 그래야 점수 추이가 남는다. 채점 전 `pending`은 앱에서 자기채점과 설명을 수정할 수 있고, 그 사이 `/채점`이 돌면 수정 전 내용으로 채점된다 (감수).
- **id(=파일명)**: 순번 + 한글 slug. 예: `0007-프로세스와-스레드의-차이`. 번역이 필요 없고 사람이 읽을 수 있다. 앞의 순번만으로 유일하다.
- **꼬리질문 중복**: `/채점`을 돌리는 Claude가 기존 질문 목록을 읽고 의미로 판단한다.
- **타이머**: 풀이 화면이 열려 있고 탭이 보이는 동안만 누적한다 (밤새 열어 둔 탭이 시간을 부풀리지 않게). `minutes`에 누적 저장.
- **녹음 파일**: git에서 제외(`.gitignore`). 받아쓴 텍스트가 기록이다. 녹음은 로컬에만 남는다.
- **기존 코드 제거 범위**: 토익 화면·SRS·퀴즈·ingest·Supabase·`/setup`·관련 테스트는 삭제한다. PWA 파일(`manifest.json`, 아이콘)은 나중 폰 지원을 위해 남긴다. 이전 스펙·플랜 문서와 git 히스토리는 그대로 둔다.
