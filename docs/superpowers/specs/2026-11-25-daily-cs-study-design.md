## 1. 왜 만드는가

- 실제 면접, 모의면접, 직접 만든 기술면접 문항에서 받은 **백엔드/CS 질문**에 대해, 내가 실제로 얼마나 설명할 수 있는지 모른다.
- 질문 하나를 잡고 1시간~하루 공부 → 조사 → **내 말로 설명** → **점수**로 이해도를 확인한다.
- 이 과정을 매일 기록하는 **나만의 공부 블로그**(읽은 기술 블로그, 오늘 공부한 것, 개발한 것, 회고)로 남긴다.
- 로컬에서 먼저 쓰고, 소셜/블로그 게시는 나중에 정한다.

**성공**: 질문별 이해도를 직관적으로 본다 — 캘린더, 그래프, 꼬리질문으로 파고들기.

## 2. 목표 · 비목표 · 실패 조건

**목표**
- 질문 은행 → 몰입형 풀이 화면(잡다 인적성 스타일) → 글/음성 설명 제출 → 자기채점
- Claude Code `/채점`으로 AI 채점, 꼬리질문 자동 생성
- 캘린더, 점수 그래프, 꼬리질문 트리, 날짜별 블로그 뷰
- 하루 회고(읽은 글, 개발한 것, 한 줄 회고) 기록

**비목표 (이번 범위 밖)**
- 폰 지원 (나중에 한다. 데이터를 평범한 md로 두어 길만 열어 둔다)
- 로그인, 서버 배포, 소셜 자동 게시, 자동 git 커밋
- 면접 대비 모드 ("내 사례" 채점 항목)
- 토익 기능 유지

**실패 조건 (동작해도 실패인 것)**
- 자기채점이 30초 안에 안 끝난다 → 매일 못 쓴다
- 기록이 앱 밖에서 못 읽는 형식이다 → 블로그로 못 옮긴다
- 앱 안에서 AI API를 호출한다 → 결정과 다르다 (비용)
- AI 채점 결과가 앱 저장으로 덮여 사라진다

## 3. 제약

- 맥 + 크롬, 로컬 개발 서버로만 쓴다. `dev` 스크립트는 `next dev -H 127.0.0.1` (맥 밖에서 접근 불가).
- 기존 셋업 유지: Next.js 16.3.0, React 19.2.8, Tailwind 4, vitest 4.
- Next.js 16은 학습 데이터와 API가 다를 수 있다. AGENTS.md가 가리키는 `node_modules/next/dist/docs/`는 **이 설치본에 없다**. 대신 context7(Next.js 16.3) 또는 nextjs.org 공식 문서로 확인하고 쓴다.
- 새 npm 패키지는 사용자에게 제안 후 추가한다 (사용자 전역 규칙).
- 데이터는 이 repo의 `data/` 폴더. git 커밋은 사용자가 직접 한다 (앱은 커밋하지 않는다).
- 파일명·id에 한글이 들어간다. 읽고 쓰고 비교할 때 항상 **NFC로 정규화**한다 (macOS 파일시스템은 NFD로 돌려줄 수 있다).

## 5. 하루 흐름

```
① 질문 고르기   질문 은행에서 오늘 할 질문 선택 → 공부 기록(draft) 생성
② 공부          [시작]을 누르면 타이머가 돈다. 링크·메모를 쌓는다. 자리를 비우면 [일시정지]
③ 설명 + 자기채점   글 쓰기 또는 말로 설명 → 기준표 항목 선택 → [제출]  (한 화면, 한 번에 확정)
④ 참고 답안 공개   제출 직후 참고 답안을 보여 준다
⑤ /채점         Claude Code에서 실행 → AI 점수, 빠진 개념, 꼬리질문 기록
⑥ 꼬리질문      생성된 꼬리질문을 새 질문으로 이어서 공부
⑦ 회고          그날의 읽은 글 / 개발한 것 / 한 줄 회고
```

### 상태 전이

| 상태 | 언제 | 누가 쓰나 | 들어 있는 것 |
|---|---|---|---|
| `draft` | ①에서 질문을 고르는 순간 파일 생성 | 앱 (자동 저장) | 메모, 링크, 누적 시간, 쓰다 만 설명 |
| `pending` | ③ [제출] 시. 설명과 자기채점이 **같이 확정**된다 | 아무도 수정 안 함 (`/채점`만 읽음) | + 설명, `self`, `self_score` |
| `graded` | `/채점`이 꼬리질문 파일까지 다 만든 뒤 | `/채점` (마지막에 한 번) | + `ai`, `ai_score`, 채점 결과, `followups` |

- 자기채점을 안 하고 닫으면 `draft`로 남는다. 다시 열면 ③ 화면으로 돌아간다. 설명만 쓰고 자기채점을 안 한 상태는 따로 없다.
- `pending`과 `graded`는 앱에서 **읽기 전용**이다. 다시 하고 싶으면 [다시 풀기]로 새 기록을 만든다. 그래서 앱과 `/채점`이 같은 파일을 동시에 쓰는 일이 없고, 잠금이 필요 없다.
- 앱은 파일을 저장하기 직전에 현재 status를 다시 읽어 `draft`가 아니면 저장을 거부한다 (오래 열어 둔 탭 보호).

### 기록 파일과 시도

- 공부 기록은 **시도** 단위다. 파일: `data/study/<날짜>/<질문id>.md`. 같은 날 같은 질문의 두 번째 시도부터 `<질문id>-2.md`, `-3.md`…
- 같은 날 같은 질문의 `draft`가 있으면 새로 만들지 않고 그 시도를 이어 한다.
- 녹음은 시도 파일과 같은 이름으로 저장한다: `<질문id>-2.webm`.
- 시도가 어느 질문인지는 **항상 frontmatter `question`으로** 찾는다 (파일명을 파싱하지 않는다).
- 날짜는 시도를 **만든 날**로 고정한다. 자정을 넘겨 이어 해도 폴더는 바뀌지 않는다.

### 타이머 (사용자 결정)

- 수동 시작/일시정지. [시작]부터 [일시정지]나 [제출]까지 센다. **다른 탭에서 글을 읽는 동안에도 계속 센다.**
- 누적 초를 `draft`에 자동 저장한다. 창을 닫았다 다시 열면 일시정지 상태로 이어진다 (닫혀 있던 시간은 세지 않는다).
- frontmatter에는 분 단위(`minutes`, 반올림)로 저장한다.

## 6. 채점 (사용자 결정)

자기채점 + Claude Code 채점 혼합. 앱은 AI를 호출하지 않는다.

**기준표 — 공부 모드 (100점)**

| 항목 | 배점 | 개념 질문에서 보는 것 | 경험 질문에서 보는 것 |
|---|---|---|---|
| `concept` | 60 | 틀린 말 없이 핵심을 짚었나 | 무엇을 했는지 구체적으로(상황·행동·결과) 말했나 |
| `tradeoff` | 40 | 왜 쓰는지, 무엇을 포기하는지 말했나 | 왜 그렇게 했는지, 다른 선택지와 무엇을 맞바꿨나 |

- 자기채점은 항목마다 0 / 절반 / 만점 3단계 (concept 0·30·60, tradeoff 0·20·40).
- AI 채점은 같은 기준표로 0~만점 정수.
- 참고 답안이 없는 질문(수동 추가, 꼬리질문)은 `/채점`이 자기 지식으로 채점한다.
- **"내 사례"는 점수 없음.** 선택 메모 칸으로만 두고 나중 면접 대비 재료로 쓴다.
- **착각 지수** = `self_score − ai_score`. `graded` 기록에만 계산한다. 양수가 크면 "안다고 착각하는 질문".

**표시 점수 (모든 화면 공통)**
- 시도의 점수 = `ai_score`, 없으면 `self_score`. `draft`는 점수 없음.
- 질문의 점수 = 그 질문의 **가장 최근 점수 있는 시도**의 점수.
- 점수를 표시할 때 AI 점수인지 자기점수인지 구분해 보여 준다 (예: 자기점수는 흐리게).

**`/채점` 명령**
- 위치: `.claude/commands/채점.md`. 구현 첫 단계에서 한글 이름 명령이 Claude Code에 뜨는지 확인하고, 안 뜨면 `.claude/commands/grade.md`(`/grade`)로 한다.
- 동작:
  1. `data/study/**/*.md` 중 `status: pending`인 시도를 모두 찾는다
  2. 질문 파일(질문 + 참고 답안 + `kind`)과 설명을 읽고 기준표로 채점
  3. 꼬리질문 2~3개를 정한다. 각각 `data/questions/` 전체를 읽고 **의미가 같은 질문이 있으면 그 id를 재사용**, 없으면 새 질문 파일을 만든다 (`source: followup`, `parent: <채점한 질문 id>`, 참고 답안 없음)
  4. 마지막에 시도 파일에 `ai`, `ai_score`, `followups`(꼬리질문 id 목록), `## 채점 결과`를 쓰고 `status: graded`로 바꾼다
- 3단계가 실패하면 4단계를 하지 않는다 → 시도는 `pending`으로 남아 다음 `/채점`에서 다시 처리된다.
- 기존 질문을 재사용할 때 그 질문의 `parent`는 바꾸지 않는다.

**꼬리질문 트리**
- 트리의 간선 = 질문 파일의 `parent` (질문 하나에 부모 하나).
- 재사용된 기존 질문은 트리에서 옮기지 않고, 시도 기록의 `followups`로만 연결된다 (시도 상세 화면에서 링크로 보여 준다).

```
data/
  questions/
    0006-프로세스와-스레드의-차이를-설명해.md   # 질문 1개 = 파일 1개, 파일명 = id
  study/
    2026-11-25/
      0006-프로세스와-스레드의-차이를-설명해.md     # 시도 1 = 블로그 글 초안
      0006-프로세스와-스레드의-차이를-설명해-2.md   # 같은 날 시도 2
      0006-프로세스와-스레드의-차이를-설명해-2.webm # 시도 2 녹음 (git 제외)
    2026-11-25.md                                # 그날 회고
```

캘린더·그래프·트리는 매번 파일을 읽어 계산하고 별도 집계 파일은 두지 않는다.

### id 규칙

- 형식: `<4자리 순번>-<한글 slug>`. 예: `0006-프로세스와-스레드의-차이를-설명해`.
- 순번 = `data/questions/`의 기존 최대 순번 + 1. 가져오기 스크립트, 앱의 "질문 추가", `/채점` 세 곳 모두 이 규칙을 쓴다.
- slug = 질문 문장에서 공백을 `-`로, 문장부호(`?`, `,`, `.`, `/` 등)는 제거, 최대 30자. NFC.
- id는 한 번 정해지면 바꾸지 않는다. 같은 질문인지는 id가 아니라 **질문 문장**(공백·문장부호 제거 후 NFC 비교)으로 판단한다.

```md
(있으면. 풀이 화면에서는 제출 전까지 숨긴다)
```

## 8. 질문 가져오기

출처: RESUME 폴더(`~/Library/Mobile Documents/com~apple~CloudDocs/me/RESUME/`)의 음성모의면접 문항 은행. 각 파일은 `var CFG = { title, file, open, close, bank: [{no, t, q, a, mine, pri}, …] }` 형태의 JS다.

| 파일 (`04_면접·코테/` 아래) | `bank` 수 | 비고 |
|---|---|---|
| `음성모의면접_문항_미리디_CS전체_20260930.js` | 37 | **정본.** 나머지 두 파일의 질문을 모두 포함 |
| `음성모의면접_문항_미리디_약점12_20260929.js` | 12 | 전부 CS전체와 중복. `open`(자기소개)은 따로 있음 |
| `음성모의면접_문항.js` | 7 | 전부 CS전체와 중복 |

규칙:
- `CFG.bank`만 가져온다. `open`, `close`는 버린다.
- 세 파일을 위 순서대로 읽고 질문 문장으로 중복을 제거한다. **처음 실행 결과 = 질문 37개, 다시 실행 = 새 질문 0개**가 합격 기준.
- `t` → `topic`, `q` → 본문, `a` → 참고 답안(HTML의 `<b>` → `**`, `<code>` → `` ` ``, 나머지 태그 제거), `mine`·`pri` → 버림. `source: mock`, `from: <CFG.title>`.
- `kind`: 질문 문장에 `경험`, `실무`, `직접`, `겪어` 중 하나가 있으면 `experience`, 아니면 `concept`. 현재 37개 중 5개가 experience다 (예: "대용량 트래픽을 다뤄 보신 경험이 있으신가요?"). 틀리게 분류된 것은 질문 파일의 `kind`를 직접 고친다.
- 가져오기는 `npm run import`로 실행하는 Node 스크립트 1개. RESUME 경로는 스크립트 인자로 받는다.

실제 면접 기록(`06_지원완료/*/`의 녹취록, `04_면접·코테/실전_미리디_기술스크리닝_20260930.md` 등)은 앱의 "질문 추가" 화면으로 수동 입력한다. 자동 추출은 하지 않는다. "질문 추가" 화면에서 `source`를 고를 때 안내: 실제 면접에서 받은 질문만 `real`, 예상질문(예: 코드잇 `예상질문.md`)·직접 만든 질문은 `self`.

## 9. 화면

**풀이 화면 (잡다 인적성 스타일, 핵심 화면)** — 전체화면 몰입형
```
┌──────────────────────────────────────────────┐
│ 운영체제 · 모의면접        ⏱ 01:15:32 [일시정지] [나가기] │
├──────────────────────────────────────────────┤
│                                              │
│   프로세스와 스레드의 차이를 설명해 주시겠어요?       │
│                                              │
├──────────────────────────────────────────────┤
│ [공부 메모] [링크]                              │
├──────────────────────────────────────────────┤
│ 설명:  (글 쓰기) (말로 설명 ●REC)                 │
│ 자기채점: 개념 ○0 ○30 ○60   트레이드오프 ○0 ○20 ○40 │
│                                      [제출]  │
└──────────────────────────────────────────────┘
```
- 제출 후 참고 답안 공개 (답안을 먼저 보면 자기채점이 오염된다).
- **말로 설명 (사용자 결정)**: `MediaRecorder`로 녹음(`.webm`)하면서 크롬 받아쓰기(Web Speech API, `ko-KR`)로 텍스트를 만든다. 받아쓰기는 음성을 구글 서버로 보낸다는 것을 사용자가 허용했다. 녹음 파일은 맥에만 저장. 받아쓴 텍스트는 제출 전에 고칠 수 있다. 마이크가 막혔거나 받아쓰기가 실패하면 녹음은 유지하고 글 쓰기로 전환한다.

**홈 / 캘린더** — 월 달력. 날짜 칸 색 농도 = 그날 만든 시도 수(`draft` 포함). 칸 안 숫자 = 그날 점수 있는 시도들의 표시 점수 평균. 날짜 클릭 → 그날 블로그 뷰.

**그래프** — 토픽별 막대(그 토픽 질문들의 질문 점수 평균), 질문별 점수 추이(시도마다 자기점수 선과 AI 점수 선), 착각 지수 큰 순 목록.

**꼬리질문 트리** — 루트 질문(`parent: null`) → 꼬리질문 → … 노드마다 질문 점수(없으면 "미학습").

**질문 은행 (사용자 결정: 경험 질문은 선택)** — 토픽·출처·점수로 필터, 그리고 **"경험 질문 포함" 토글 (기본 꺼짐)**. 정렬: 미학습 / 채점 대기 / 낮은 점수 순. "질문 추가" 버튼.

**블로그 뷰 (날짜별)** — 그날의 시도들 + 회고를 한 페이지로. 회고 작성/수정도 여기서. 시도 상세에서 `followups` 링크를 보여 준다.
