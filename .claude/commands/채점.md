데일리 CS 앱의 `status: pending` 시도를 채점한다. 이 저장소 루트에서 실행한다. 데이터 루트는 `data/`다. 아래 순서와 파일 형식을 글자 그대로 따른다.

## 0. 대상 찾기

`data/study/*/*.md` (날짜 폴더 안의 `.md`, `data/study/YYYY-MM-DD.md` 회고 파일은 제외) 중 frontmatter에 `status: pending` 이 있는 파일을 모두 찾는다. 없으면 `채점 대기 없음` 한 줄만 말하고 끝낸다. 있으면 시도마다 1~5단계를 차례로 처리한다.

## 1. 읽기

- 시도 파일: frontmatter(`question`, `self`, `self_score` ...)와 `## 내 설명`(채점 대상), `## 공부 메모`, `## 내 사례 (선택)`.
- 질문 파일 `data/questions/<question>.md`: 첫 줄들이 질문 문장, `## 참고 답안` 이 있으면 그 아래가 참고 답안, frontmatter의 `kind`(`concept` | `experience`)와 `topic`.
- 한글 파일명은 NFC/NFD가 섞일 수 있다. 셸 glob 대신 아래 node 도구를 쓰면 안전하다.
- 파일명이 id다 (`.md` 제외).

## 2. 채점

`## 내 설명`만 채점한다. `## 내 사례 (선택)`은 점수가 없다. 참고 답안이 없으면 자기 지식으로 채점한다. 자기채점(`self`)은 보되 휘둘리지 않는다.

| 항목 | 배점 | `kind: concept` 에서 보는 것 | `kind: experience` 에서 보는 것 |
|---|---|---|---|
| `concept` | 60 | 틀린 말 없이 핵심을 짚었나 | 무엇을 했는지 구체적으로(상황·행동·결과) 말했나 |
| `tradeoff` | 40 | 왜 쓰는지, 무엇을 포기하는지 말했나 | 왜 그렇게 했는지, 다른 선택지와 무엇을 맞바꿨나 |

- `ai.concept` 는 정수 0..60, `ai.tradeoff` 는 정수 0..40 (자기채점의 0/30/60 단계와 달리 중간값 허용).
- `ai_score = ai.concept + ai.tradeoff`.
- 경험 질문은 정답이 없다. 설명이 구체적이고 일관된지를 본다. 지어낸 듯한 모순이 있으면 근거에 적는다.


## 3. 꼬리질문 2~3개 정하기

면접관이 이어서 물을 만한 질문을 2~3개 정한다 (빠진 개념, 얕았던 부분을 파고드는 질문). 질문마다:

1. 먼저 기존 질문 문장을 모두 읽는다 (이 명령은 산문이 없다):

```bash
node --input-type=module <<'EOF'
import { listQuestions } from './lib/questions.mjs';
for (const q of listQuestions('data')) console.log(q.id, '|', q.text.replace(/\n/g, ' '));
EOF
```

2. **의미가 같은 질문이 이미 있으면 그 id를 재사용**한다 (`{ "id": "<기존 id>" }`). 그 질문 파일은 수정하지 않는다 (`parent` 도 그대로).
3. 없으면 새 질문이다 (`{ "text": "<질문 문장>" }`). 질문 문장 하나, 한국어 면접 말투. 4단계 스크립트가 `createQuestion` 으로 만든다 (id 부여, 문장 기준 중복 제거, `kind` 자동 결정, `topic` 은 채점한 질문의 것, `source: followup`, `parent: <채점한 질문 id>`, `from: null`, `created: <오늘>`, 참고 답안 없음).
4. **채점한 질문 자신의 id는 꼬리질문으로 쓰지 않는다.** 그 질문과 같은 문장도 안 된다.

## 4. 시도 파일 갱신 (한 번에, 꼬리질문 파일 생성 → 시도 갱신 순서)

**셸 따옴표 안에 모델이 쓴 문장(근거, 질문 문장 등)을 넣지 않는다.** 따옴표·백틱·`$`·`"` 가 깨지거나 글이 바뀐다. 채점 내용은 JSON 파일에 쓰고, 스크립트는 그 파일을 읽기만 한다.

### 4-1. payload JSON 파일 쓰기

Write 도구로 임시 위치(예: `/tmp/grading-<시도 파일 이름>.json`, 저장소 밖)에 시도 하나당 파일 하나를 만든다:

```json
{
  "attempt": "data/study/2026-11-25/0006-프로세스와-스레드의-차이를-설명해.md",
  "ai": { "concept": 45, "tradeoff": 20 },
  "followups": [
    { "text": "컨텍스트 스위칭은 왜 비용이 드나요?" },
    { "id": "0008-뮤텍스와-세마포어의-차이를-설명해-주시겠어요" }
  ],
  "result": "- 빠진 개념: ...\n- 근거: ..."
}
```

- `attempt`: 시도 파일 경로 (`data/study/YYYY-MM-DD/<파일>.md`). 실제 파일명을 1단계에서 읽은 그대로 쓴다.
- `ai.concept` 는 정수 0..60, `ai.tradeoff` 는 정수 0..40 (스크립트가 검사하고 어기면 아무것도 쓰지 않고 멈춘다). `ai_score` 는 스크립트가 합산한다.
- `followups`: 2~3개. 항목은 `{ "id": 기존 질문 id }` 또는 `{ "text": 새 질문 문장 }`.
- `result`: `## 채점 결과` 섹션 본문. 줄바꿈은 `\n`, `"` 는 `\"`.

### 4-2. 스크립트 실행

저장소 루트에서, 아래 heredoc을 **그대로** 실행한다 (따옴표 `'EOF'` 필수, `PAYLOAD` 경로만 바꾼다):

```bash
PAYLOAD=/tmp/grading-<시도 파일 이름>.json node --input-type=module <<'EOF'
import fs from 'node:fs';
import { parse, stringify, setSection } from './lib/frontmatter.mjs';
import { createQuestion, readQuestion } from './lib/questions.mjs';

const p = JSON.parse(fs.readFileSync(process.env.PAYLOAD, 'utf8'));
const { concept, tradeoff } = p.ai ?? {};
if (!Number.isInteger(concept) || concept < 0 || concept > 60) throw new Error('ai.concept must be an integer 0..60');
if (!Number.isInteger(tradeoff) || tradeoff < 0 || tradeoff > 40) throw new Error('ai.tradeoff must be an integer 0..40');
if (!Array.isArray(p.followups) || p.followups.length < 2 || p.followups.length > 3) throw new Error('need 2-3 followups');
if (typeof p.result !== 'string' || !p.result.trim()) throw new Error('result is empty');

const { data, body } = parse(fs.readFileSync(p.attempt, 'utf8'));
if (data.status !== 'pending') throw new Error('attempt is not pending');
const qid = String(data.question).normalize('NFC');
const parentQ = readQuestion('data', qid);
if (!parentQ) throw new Error('question not found: ' + qid);

const d = new Date();
const pad = (n) => String(n).padStart(2, '0');
const today = `${d.getFullYear()}-${pad(d.getMonth() + 1)}-${pad(d.getDate())}`;

// 1) follow-up question files first. Any throw here leaves the attempt pending.
const ids = [];
for (const f of p.followups) {
  let id;
  if (f.id) {
    id = String(f.id).normalize('NFC');
    if (!readQuestion('data', id)) throw new Error('followup id not found: ' + id);
  } else {
    id = createQuestion('data', { text: f.text, topic: parentQ.topic, source: 'followup', parent: qid, from: null, created: today }).question.id;
  }
  if (id === qid) throw new Error('a followup must not be the graded question itself');
  if (!ids.includes(id)) ids.push(id);
}

// 2) only then update the attempt
data.status = 'graded';
data.ai = { concept, tradeoff };
data.ai_score = concept + tradeoff;
data.followups = ids;
fs.writeFileSync(p.attempt, stringify(data, setSection(body, '채점 결과', p.result.trim())));
console.log('graded', p.attempt, data.ai_score, ids.join(' '));
EOF
```

- 스크립트가 던지면 시도는 `pending` 으로 남는다. 이미 만들어진 꼬리질문은 다음 실행 때 문장 중복 제거로 재사용되니 원인을 고치고 같은 payload로 다시 실행한다.
- 시도 파일은 `status` 변경, `ai`, `ai_score`, `followups` 추가, `## 채점 결과` 섹션 추가만 바뀐다. 다른 키와 본문(`## 공부 메모`, `## 내 설명`, `## 내 사례 (선택)`)은 그대로다. (`self: { ... }` 가 compact JSON 으로 다시 쓰이는 것은 정상이다.)
- 새 질문 파일을 직접 만들 필요는 없다. 만약 꼭 필요하면 형식은 `lib/questions.mjs` 의 `createQuestion` 이 쓰는 것과 같다 (id = `lib/ids.mjs` 의 `makeId(최대 순번 + 1, 문장)`, frontmatter `id/topic/kind/source: followup/from: null/parent/created`, 본문은 질문 문장, 값 인코딩은 `lib/frontmatter.mjs`).

## 5. 끝나면

저장 후 시도 파일과 새 질문 파일을 다시 읽어 `status: graded`, `ai_score == ai.concept + ai.tradeoff`, `followups` 의 모든 id가 `data/questions/` 에 있는지 확인한다. 그리고 시도마다 한 줄씩 요약한다:

`<질문 문장 앞부분> · 자기 <self_score> → AI <ai_score> (착각 지수 <self_score - ai_score>)`

다른 파일은 고치지 않는다. 앱 코드나 `.gitignore`, 커밋은 건드리지 않는다.
