데일리 CS 앱의 `status: pending` 시도를 채점한다. 이 저장소 루트에서 실행한다. 데이터 루트는 `data/`다. 아래 순서와 파일 형식을 글자 그대로 따른다.

## 0. 대상 찾기

`data/study/*/*.md` (날짜 폴더 안의 `.md`, `data/study/YYYY-MM-DD.md` 회고 파일은 제외) 중 frontmatter에 `status: pending` 이 있는 파일을 모두 찾는다. 없으면 `채점 대기 없음` 한 줄만 말하고 끝낸다. 있으면 시도마다 1~5단계를 차례로 처리한다.

## 1. 읽기

- 시도 파일: frontmatter(`question`, `self`, `self_score` ...)와 `## 내 설명`(채점 대상), `## 공부 메모`, `## 내 사례 (선택)`.
- 질문 파일 `data/questions/<question>.md`: 첫 줄들이 질문 문장, `## 참고 답안` 이 있으면 그 아래가 참고 답안, frontmatter의 `kind`(`concept` | `experience`)와 `topic`.
- 한글 파일명은 NFC/NFD가 섞일 수 있다. 셸 glob 대신 아래 `node -e` 도구를 쓰면 안전하다.
- 파일명이 id다 (`.md` 제외).

## 2. 채점

`## 내 설명`만 채점한다. `## 내 사례 (선택)`은 점수가 없다. 참고 답안이 없으면 자기 지식으로 채점한다. 자기채점(`self`)은 보되 휘둘리지 않는다.

| 항목 | 배점 | `kind: concept` 에서 보는 것 | `kind: experience` 에서 보는 것 |
|---|---|---|---|
| `concept` | 60 | 틀린 말 없이 핵심을 짚었나 | 무엇을 했는지 구체적으로(상황·행동·결과) 말했나 |
| `tradeoff` | 40 | 왜 쓰는지, 무엇을 포기하는지 말했나 | 왜 그렇게 했는지, 다른 선택지와 무엇을 맞바꿨나 |

- `ai.concept` 는 정수 0..60, `ai.tradeoff` 는 정수 0..40 (자기채점의 0/30/60 단계와 달리 중간값 허용).
- `ai_score = ai.concept + ai.tradeoff`.
- 경험 질문은 정답이 없다. 설명이 구체적이고 일관된지를 본다. 지어낸 듯한 모순이 있으면 근거에 적는다.

## 3. 꼬리질문 2~3개

면접관이 이어서 물을 만한 질문을 2~3개 정한다 (빠진 개념, 얕았던 부분을 파고드는 질문). 질문마다:

1. `data/questions/` 의 모든 질문 문장을 읽는다 (`listQuestions`, 아래 도구). **의미가 같은 질문이 이미 있으면 그 id를 재사용**한다. 그 질문 파일은 수정하지 않는다 (`parent` 도 그대로).
2. 없으면 새 질문 파일을 만든다. 직접 만들지 말고 아래 `createQuestion` 을 쓴다 (id, 문장 기준 중복 제거, `kind` 가 처리된다).
   - `text`: 질문 문장 하나 (한국어, 면접 말투)
   - `topic`: 채점한 질문의 `topic`
   - `source: 'followup'`, `parent: <채점한 질문 id>`, `from: null`, `created: <오늘 YYYY-MM-DD>`
   - `answer` 는 넣지 않는다 (참고 답안 섹션 없음)
   - `kind` 는 생략한다 (문장에 `경험|실무|직접|겪어` 가 있으면 `experience`, 아니면 `concept` 로 자동 결정).
   - 반환된 `question.id` 를 followups 에 모은다. `created: false` 가 돌아오면 문장이 완전히 같아 기존 것이 재사용된 것이니 그대로 그 id를 쓴다.

도구 (저장소 루트에서 실행. 한 질문마다 호출해 순번이 이어지게 한다):

```bash
# 기존 질문 전체 보기
node -e "import('./lib/questions.mjs').then(m=>{for(const q of m.listQuestions('data'))console.log(q.id,'|',q.text.replace(/\n/g,' '))})"

# 새 꼬리질문 만들기
node -e "import('./lib/questions.mjs').then(m=>{const r=m.createQuestion('data',{text:'컨텍스트 스위칭은 왜 비용이 드나요?',topic:'운영체제',source:'followup',parent:'0006-프로세스와-스레드의-차이를-설명해',from:null,created:'2026-11-25'});console.log(r.created,r.question.id)})"
```

직접 파일을 만들어야 하면 형식은 다음과 같다 (`lib/frontmatter.mjs` 규칙):

- id = `NNNN-slug`. NNNN = `data/questions/` 최대 순번 + 1 (4자리). slug = 공백→`-`, 글자·숫자·`-` 외 전부 제거(문장부호, `+`, `#` 포함), 앞뒤 `-` 제거, 최대 30 코드포인트, NFC. slug가 비면 `NNNN` 만. `lib/ids.mjs` 의 `makeId(seq, text)` 가 정확한 구현이다.
- 파일 `data/questions/<id>.md`:

```
---
id: <id>
topic: <topic>
kind: concept
source: followup
from: null
parent: <채점한 질문 id>
created: 2026-11-25
---
<질문 문장>
```

- frontmatter 값: `[0-9A-Za-z가-힣_-./]` 만으로 된 문자열(id, 날짜, `followup`)은 따옴표 없이, 그 밖의 문자열(공백·`:`·`#`·따옴표 포함)·객체·배열은 JSON(`"..."`, `{ "concept": 45 }`, `["a","b"]`)으로 쓴다. 숫자·`null` 은 그대로.
- 질문 중복 판정 기준은 id가 아니라 문장이다 (공백·문장부호 제거 후 NFC 비교, `+` `#` 는 유지).

## 4. 시도 파일 갱신 (꼬리질문 파일을 **모두 만든 뒤에만**)

3단계가 하나라도 실패하면 이 시도의 4단계를 하지 않는다. 시도는 `pending` 으로 남아 다음 `/채점` 에서 다시 처리된다 (이미 만든 질문은 문장 중복 제거로 재사용된다).

시도 파일에 다음만 추가·변경한다. 다른 키와 본문(`## 공부 메모`, `## 내 설명`, `## 내 사례 (선택)`)은 건드리지 않는다.

- frontmatter: `status: graded` 로 변경, 그리고 추가
  - `ai: { "concept": 45, "tradeoff": 20 }`
  - `ai_score: 65`
  - `followups: ["0038-...", "0012-..."]` (JSON 배열, 꼬리질문 id 2~3개, 재사용 id 포함)
- 본문 끝에 섹션 추가 (정확히 `## 채점 결과` 줄):

```
## 채점 결과
- 빠진 개념: ...
- 근거: ...
```

안전한 방법 (한글 파일명은 파일 경로를 `readdir` 로 찾는다):

```bash
node -e "
import('./lib/frontmatter.mjs').then(async f=>{
  const fs=await import('node:fs');
  const p='data/study/2026-11-25/<파일명>.md';
  const {data,body}=f.parse(fs.readFileSync(p,'utf8'));
  data.status='graded';
  data.ai={concept:45,tradeoff:20};
  data.ai_score=65;
  data.followups=['<id1>','<id2>'];
  fs.writeFileSync(p,f.stringify(data,f.setSection(body,'채점 결과','- 빠진 개념: ...\n- 근거: ...')));
})"
```

`stringify` 는 키 순서를 유지하고 `status` 는 제자리에서 바뀐다. 파일 경로의 한글이 안 맞으면 `fs.readdirSync` 로 `normalize('NFC')` 비교해 실제 이름을 찾는다.

## 5. 끝나면

저장 후 `data/study/.../*.md` 를 다시 읽어 `status: graded`, `ai_score == ai.concept + ai.tradeoff`, `followups` 의 모든 id가 `data/questions/` 에 있는지 확인한다. 그리고 시도마다 한 줄씩 요약한다:

`<질문 문장 앞부분> · 자기 <self_score> → AI <ai_score> (착각 지수 <self_score - ai_score>)`

다른 파일은 고치지 않는다. 앱 코드나 `.gitignore`, 커밋은 건드리지 않는다.
